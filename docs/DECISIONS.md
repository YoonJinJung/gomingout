| D6 | 만 14세 이상만 가입 | 14세 미만은 법정대리인 동의 절차가 필요하므로 제외 |
| D7 | 1인 풀스택, pnpm 모노레포 + 공유 타입 패키지 | 프론트·백 타입/검증 일치 |
| D8 | 신고+자동 블라인드+어드민, 위기 키워드 안내를 MVP 포함 | 실제 배포 시 필수 안전장치 |
| D9 | 익명 글·댓글의 MBTI 기본 표시, 작성 시 끌 수 있음. 다른 프로필 항목은 익명 글에 절대 노출 금지 | 조합 노출 시 특정 가능성 |
| D10 | 카테고리 대분류-소분류 2단계, 시드 관리 | 다양한 고민 분야 |
| D11 | 게시글은 텍스트만 | 스토리지·이미지 검수 부담 제거 |
| D12 | 피드: 최신 + 인기(시간 감쇠) + 홈 인기글 섹션 | - |
| D14 | 디자인 콘셉트: "밤에 조용히 털어놓는 곳". 어두운 남색 + 라벤더 | 고민을 주로 밤에 나누는 사용 맥락 |
| D15 | 다크 모드 기본, 라이트는 토큰만 정의 후 M7에서 전환 추가 | 1인 개발 범위 관리 |
| D16 | 글쓰기 기본값 익명 ON (제안) | 고민상담 특성상 익명 선호 예상 |
| D17 | 로컬에서 전 기능 완성 후 배포(M8). 로컬은 Docker(Postgres, Mailpit), 배포 호환 구조 유지 | 개발 속도 우선, 배포 시 구조 변경 최소화 |
| D18 | 대댓글 1단계, 댓글 공감 허용, 탈퇴 시 글은 남기고 "탈퇴한 사용자" 표시 | 추천안 채택 |
| D13 | 배포: Vercel(web + Express) + Supabase Postgres(서울) | 1인 개발 인프라 부담 최소화. AWS 요건 없음 |
| D19 | 로컬에서 이메일 인증은 mock 가능(`EMAIL_PROVIDER=mock`, 인증 코드를 콘솔 출력). 보고서·스크린샷용 고정 테스트 계정을 시드로 만든다 | 배포 단계가 아니라 기능 완성이 목적이므로 실제 메일 발송이 경로에 끼어들 필요가 없다 |
| D20 | 카테고리 대분류 "몸"을 "외모"로 바꾸고 소분류를 다이어트·피부·헤어·건강으로 정리 | "몸"이라는 분류명이 부담스럽다는 판단 |
| D21 | M0 UI는 실제 API 대신 `PublicPost`·`PublicComment` 타입으로 타이핑한 mock 픽스처로 구성한다 | 스키마(M1~M3)를 앞당기지 않고 화면 구성을 먼저 확인하기 위해. 타입이 같으므로 실제 API로 바꿀 때 화면 코드를 고칠 필요가 없다 |
| D22 | **`글쓴이` 배지는 글의 익명 여부와 무관하게 항상 표시한다.** 닉네임 글 + 익명 댓글이어도 `글쓴이`로 표시 | 대화 맥락상 글쓴이의 답글임을 아는 것이 더 중요하다는 판단. 단, 닉네임 글에 익명 댓글을 달면 그 댓글의 작성자가 글쓴이임이 드러난다는 점을 글쓰기·댓글 화면에서 안내한다 |
| D23 | 댓글 공감을 위해 `CommentLike` 모델을 스키마에 추가하고 `POST/DELETE /comments/:id/like` API를 정의한다 | D18에서 댓글 공감이 확정됐으나 `Comment.likeCount`를 유지할 수단이 없었다 |

## 기술 세부 (제안 기본값, 이의 없으면 확정)
| ID | 내용 |
|---|---|
| T1 | Supabase는 DB로만 사용(Supabase Auth 미사용) → 백엔드 이식성 유지 |
| T2 | Prisma: `DATABASE_URL`은 Supabase 풀러(트랜잭션 모드, pgbouncer=true), `DIRECT_URL`은 마이그레이션용 직접 연결 |
| T3 | web의 `/api/*`를 api Vercel 프로젝트로 rewrite → 같은 도메인, 쿠키 문제 없음 |
| T4 | 인증: access token(JWT, 15분) + refresh token(DB 저장·해시, 30일), 둘 다 httpOnly 쿠키 |
| T5 | 비밀번호 해싱 bcryptjs (서버리스 네이티브 모듈 이슈 회피) |
| T6 | 이메일 발송 Resend, rate limit Upstash Redis |
| T7 | 인기 점수는 조회 시 SQL 계산(크론 없음) |
| T8 | PWA는 Serwist 사용 |

## 리스크 메모
- Vercel Hobby 플랜은 비상업적 용도 전제 → 실서비스화 시 유료 전환 검토
- Supabase 무료 프로젝트는 일정 기간 비활성 시 일시정지될 수 있음 → 시연 전 확인
- iOS PWA 웹 푸시는 홈 화면 설치 시에만 동작(알림 기능 도입 시 고려)
